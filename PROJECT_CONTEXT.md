- **Data restore & sync (v39–v40, important):** iOS **wipes a PWA's IndexedDB when its home-screen icon is removed** — a reinstall starts empty; the Supabase `entries` table is the backstop. Three bugs made this look like permanent loss and are now fixed:
  1. **Un-paginated pull** — `syncFromSupabase` `select()` hit PostgREST's **1000-row cap**, and `entries` holds every store (workout+calories), so past 1000 total rows the pull silently dropped sessions while the few routine rows survived. Now **paginated** (`.range()` loop, ordered by store+key).
  2. **Per-write `auth.getUser()`** — every `db.set` did a network auth call; a bulk import fired hundreds concurrently → rate-limited → most cloud writes silently dropped. Now the uid is **cached** (`_uidPromise`).
  3. **Render-before-restore** — `db.js` exports **`initialSync`** (resolves to rows restored); `app.js` init **awaits it (12 s cap) before first render/seed**, re-renders if late, shows "Restoring…". 
  `db.backup()` (`syncToSupabase`) pushes all local rows up in batches. Stats → **Backup & restore**: "Restore from cloud" (reports item + workout counts — the diagnostic for "is my history in the cloud?"), "Back up to cloud now", "Export backup file" (JSON download), "Import workouts (CSV/JSON)". Nothing deletes `session-*` in the cloud except the explicit "Clear all history" button; `upsert` never deletes, so "Back up" is always safe. Do NOT weaken any of this (e.g. render before the pull, or drop pagination).
- **No "Hevy" branding** — the app is standalone. All user-facing mentions removed (import is "Import workouts (CSV/JSON)", streak seed is "a previous streak"); the CSV parser is `parseWorkoutCSV` (still understands the common tracker column layout). Only the invisible internal `stableId` `'hevy-'` key prefix remains (changing it would break dedup of already-imported sessions).
- **Auth:** Supabase email **OTP code** (not magic link). Session faked in preview via `localStorage['sb-xjcnkivlkfzdycbyxxlx-auth-token']`.
- **Service worker:** network-first + `cache:'no-cache'`; auto-updates (polls every 60s, reloads on controllerchange). If updates won't land: delete PWA + re-add.

## Workout data model (IndexedDB store `'workout'`)
- `session-<id>` → `{id, title, date:'YYYY-MM-DD', startTime:ISO, endTime, duration:secs, exercises:[...], pbs:[{exercise,type,label}]}`. `prevPerf`/`prevSets` are stripped before saving — they're transient ghosting aids for the live editor, not part of the historical record.
- exercise (in session): `{id, name, category, logType, repRange:{min,max}|null, restTime, notes, sets:[...]}` (`prevPerf`/`prevSets` present only while a workout is in progress)
- set: `{id, type:'normal'|'warmup'|'dropset', weight, reps, done, rpe?, touched:{weight,reps}, tW, tR}` (tW/tR = ghost targets, stripped on save)
- `templates` → array `{id, name, exercises:[{name, category, restTime, sets:[{weight,reps,type}]}]}`
- `exercises-custom` → array `{id, name, category, custom:true, logType, repRange?:{min,max}}` — `repRange` is filled in asynchronously by the AI lookup (see `repRanges.js` above) and absent until that resolves.
- Other keys: `streak-settings {seed,seedDate,target}`, `active-session`, `active-rest`, `coach-thread`, `anthropic-key`, `replacement-prefs`, `my-routines-seeded`, `push-day-fixed`.
- **Redesign (v58) keys:** `bodyweight-log` → `[{date:'YYYY-MM-DD', kg}]` (see `getBodyLog`/`logBodyweight`/`bodyStats`), `week-plan` → `{ 'YYYY-MM-DD': templateId }` (per-day routine assignments, see `getWeekPlanMap`/`setPlanDay`). Both live in the `workout` store so they sync + back up like everything else.
- **Exercise identity / aliases (v63):** `exercise-aliases` → `{ rawNameLower: canonicalName }` — user-declared "these logged names are the same lift" merges. `canonicalName(name)` (app.js) folds any variation/custom name onto its chosen identity (one-hop chain, cycle-guarded, case-insensitive), applied at **read time** so no stored session is ever rewritten (fully reversible via "Separate"). Wired through everywhere history groups by name: `buildExerciseStatsMap` (canonical key), `openExerciseDetail` (opens the canonical, merges recent-sets + tags each variation, merges the progression chart via `canonicalizeSessions`), `collectPRs`/PR timeline, the Progress-tab frequency dropdown + progression, Library (members hidden — `visible` list), and the AI coach (both `assembleContext` calls use `loadSessionsCanonical`). UI lives on the exercise-detail overlay's **Identity card** (Merge picker `#mergeExModal` + per-member ✕). `canonicalizeSessions(sessions)` returns a shallow-cloned canonical view for the name-grouping helpers in `stats.js`/`coach.js` (which have no access to the alias map). NB: the exercise **picker is intentionally NOT deduped** — logging under an old name is harmless since it auto-merges on read.
- **Cardio today:** `category:'Cardio'` sets reuse `reps` as minutes; volume calc skips them. No dedicated per-exercise tracking-type field yet (planned).
- **Editable exercise (v58):** the active-workout `…` sheet has an **Edit exercise…** row → `openEditExerciseModal(ei)` (`#editExModal`) to change an exercise's **name** (custom only — built-in names are fixed/read-only), **muscle group** and **tracking type**. It **writes to the core library**: custom exercises edit their `exercises-custom` entry in place; built-ins record an override in a new `workout` store key **`exercises-overrides`** = `{ [canonicalName]: {category?, logType?} }`. Loaded once at init into module cache `exOverrides` via `loadExOverrides()` (before first render) and re-saved on each edit. `resolveLogType(ex)` is **override-first** (`exOverrides[ex.name].logType` wins over the BODYWEIGHT regex and any baked/session logType) and `getAllExercises()` merges overrides onto the built-in list, so an edit applies everywhere (picker, Library, coach allow-list, live blocks). Synced to cloud automatically (syncToSupabase walks all keys). NB: `Crunch` is now `logType:'bodyweight'` in `exercises.js` (reps-only) while `Cable Crunch` stays weighted.

## Conventions / gotchas
- No build — edit, commit, push. Bump `sw.js` CACHE. Commit trailer `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- Inputs must be ≥16px (iOS zoom). Viewport has `maximum-scale=1,user-scalable=no`. `touch-action:manipulation`. Set rows/inputs `touch-action:pan-y` (swipes).
- Sections need bottom padding for the fixed 56px tab bar: `.section { padding: 0 var(--gap) calc(env(safe-area-inset-bottom)+72px); }`.
- **Tab bar (`.tabs`) must anchor `bottom:0` with `height: calc(56px + env(safe-area-inset-bottom))` + `padding-bottom: env(safe-area-inset-bottom)`** — NOT `bottom: env(safe-area-inset-bottom)`, which lifts the bar ~34px off the bottom on home-indicator iPhones and lets the scrolling page show through the transparent strip beneath it. Buttons live in the top 56px (above the home indicator); the padding is opaque backing. Its top edge stays at `56px + inset`, so `#secCoach.active` (`bottom: calc(56px + env(safe-area-inset-bottom))`) and `#miniBar` (`bottom: calc(env(safe-area-inset-bottom) + 58px)`) still align.
- Dynamic Island / native home-screen widgets / live audio while backgrounded: **impossible in a PWA** (communicated + declined).
- `esc()` (in both `app.js` and `stats.js`) escapes quotes as well as `<>&` — exercise names are free-typed user input and get interpolated into HTML attributes (`data-cue="..."`, `data-name="..."`) in several places, so don't regress this back to an `<>&`-only escaper.
- The `DURATION_NAMES` regex (app.js) intentionally does **not** match bare `hang` — only `dead hang` — because bare `hang` false-matched "Leg Raise (Hanging)" and forced a rep-based exercise into time-tracking.
